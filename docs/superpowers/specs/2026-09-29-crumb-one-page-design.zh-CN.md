# Crumb：成员一页版、自觉记账与批量请下午茶

状态：已实施（2026-09-30，分支 `feature/one-page`）；设计于 2026-09-29 批准。本文按实际做出来的样子描述；实施中定下的、和批准稿不一样的地方集中列在 §16。
基线：0.1 版（`main` 上的自托管版，合并提交 `643e237`）。
英文版：[2026-09-29-crumb-one-page-design.md](2026-09-29-crumb-one-page-design.md)。

## 1. 目标与已定决定

Crumb 回到它最初的样子：成员打开就是一页，一眼看完可用额度和收藏架；管理端只留必要的；任何小店（面包店、咖啡厅、奶茶店，或别的小团队）下载下来，换上自己的名字、图标和称呼就能用，不需要学。

已定：

- **成员端一页**，不分页、不加底部标签。页面顺序：页头一行 →「放到手机桌面」提示卡（点「知道了」之前）→ 主卡（名字、额度名、像素大数字、收藏格、下一件正在烤箱里）→ 动作区 → 记录条 → 欢迎语 → 页脚。
- **两种花钱方式**，建团队时选、所有者随时可改：**自觉制**（界面叫「自己记」：成员自己按键盘记金额，当场扣）和**确认制**（界面叫「要确认」：成员从福利清单申请，管理员确认后扣）。默认自觉制。
- **管理端压成两页**：「团队」一页放请下午茶、等你点头、大家、福利、记录；「设置」一页放组织设置、花钱方式和操作日志。原「概览 / 成员 / 福利 / 兑换 / 历史 / 活动」六个子页取消，它们的旧地址（如 `#/team/members`）落到现在承载它的那一页。
- **批量请下午茶**：一次给多个人同一金额。
- **视觉回到原版画风**：一张厚底影的白砖主卡、像素字大数字、带内阴影的收藏格、木色的记录条、3D 按钮。去掉原来的 2px 边框卡片和三行页头。
- **五处动画**：开场出炉、主卡滑入、大数字滚动、点心落格、点吉祥物掉屑。不做「咬一口」。
- **措辞**：应用文案里的「认可 / recognition」改为「下午茶 / treat」。README 的标语和简介句（公共演示页和它共用）本轮不改。
- **登录方式不变**：成员用专属链接或二维码，所有者和管理员用密码。
- **主题换皮（面包店、咖啡店）留到下一轮**，本轮保持像素点心。

## 2. 成员页

从上到下：

1. **页头一行**。左边：吉祥物（老婆饼；组织上传了 logo 就显示 logo）加团队名，点吉祥物会抖一下、掉饼屑。右边：成员名字，做成一个小胶囊，点开是「语言」和「退出登录」。没有别的导航。
2. **「把 Crumb 放到手机桌面」提示卡**（现有）：只给成员看，在这台设备上点「知道了」后不再显示。
3. **主卡**：
   - 名字；
   - 额度名（组织设置里的称呼，如「Café credit」），小号、加字距；
   - 可用余额，像素字大数字（画在 canvas 上；读屏软件读的是同一数额的文字）；
   - 收藏格：每行六格，显示已解锁的点心，空格补满到下一整行；点一下格子显示点心名字；
   - 「**{下一件} 正在烤箱里**」，配这件的小图；集齐时改成「全部 {total} 件都到齐啦。下午茶照样算数。」
   - 不显示累计收到的数额、总件数和台阶：多久出一件是个惊喜，成员也无法靠任何动作加速。
4. **动作区**，按花钱方式二选一：
   - 自觉制：一个「我拿了东西」按钮，弹出面板（手机上从底部升起，带抓手条）：「拿了多少？」、可用余额（「还有 $106.50 可以花」）、数字键盘（0–9、「清空」、「删一位」）和「记下」。超过余额时面板写「超啦，余额没这么多」，「记下」按不了。确认后当场扣，大数字滚到新值、轻轻一缩，记录条原地换成新的，提示「记好了，$12.50。工作了一天，放松一下吧~」。
   - 确认制：福利清单（图标〔有就显示〕、名称、说明、价格、「来一份」；余额差一点时写「再攒一点就够啦」）和「我的申请」（等待确认的可取消）。这句只在差额大于零、且不超过这项福利价格的一半时出现；差得更多就不写，价格和按不了的「来一份」照旧。
   - 动作区下面一句灰字：每天一句暖心话，按日期在七句里轮换（如「累了就吃口甜的。」）；可用余额为零时换成更温和的四句之一（如「空的也没关系，辛苦了。」）。
   - 切到自觉制以后，还在等确认的申请仍以「我的申请」一块显示，直到确认、拒绝或取消。
5. **记录条**：木色标题栏「记录 · 最近」，默认显示最近五条；点「看全部」变成「记录 · 全部」，按月分组，「显示更多」用现有的分页接口每次再加载 25 条；「收起」回到最近五条。最近五条每行四样：菱形、正负金额、类别、日期。类别是：下午茶、自己记的、兑换、退回、改动（收回的下午茶和改回的记账都叫「改动」）。被更正过的那一行多一个标记：下午茶「收回了」，自己记的「改回了」，兑换「已退回」。展开后每行写得完整些（「Priya 请的」「自己记的」「改回了一笔记错的」），下午茶的留言作为行下的小字显示；最近五条里不显示留言。
6. **欢迎语**：组织设置里的那段话，放页面最底一行小字。没设就不显示。
7. **页脚**：联系管理员、反馈、版本号，字更小。

这台设备上次看过之后又收到了下午茶：大数字往上跳，并提示「有人请你下午茶啦，+$30.00」。

所有者和管理员也有自己的这一页（导航里叫「我的」），他们也能收到下午茶。

## 3. 花钱方式

组织设置新增 `spending`：`self`（自觉制）或 `confirm`（确认制）。建团队时选（「大家怎么花」），默认 `self`；所有者在设置里随时可改，不受奖励规则锁定的限制。

**自觉制**：

- 成员调用 `POST /api/me/spend`，带金额、单位（`mode`）和幂等键。服务器在同一笔事务里检查：账号在职、金额大于零、单位和组织当前的一致、不超过当前可用余额、积分模式下是整数。
- 记账为一条账目，`kind = 'spend'`，负数，`actor` 是成员本人，没有来源行；操作日志记一条 `spend.create`。
- 记错了由管理员更正：`POST /api/admin/spends/:id/void`，必须写原因；加一条 `kind = 'void'` 的正数账目，指向那条 `spend`；每条只能更正一次（再来一次返回 `ALREADY_CORRECTED`，不是 `spend` 的返回 `ENTRY_NOT_FOUND`）；操作日志记一条 `spend.void`。成员自己不能撤销。
- `spend` 和 `void` 都不影响「累计收到」：收藏只看下午茶。
- 自觉制下成员页不显示福利清单，新申请返回 `SPENDING_MODE`。福利本身留着，切回确认制时还在。反过来，确认制下 `POST /api/me/spend` 也返回 `SPENDING_MODE`。还停在旧花法上的页面会收到这个答复，提示刷新一下。

**确认制**：现有做法不变。

**切换**：

- 自觉制 → 确认制：成员页出现福利清单（管理员添加前是空的）；「我拿了东西」按钮消失。
- 确认制 → 自觉制：福利清单和「来一份」消失；还没处理的申请照常留在成员的「我的申请」和管理员的「等你点头」里，直到确认、拒绝或取消。

CSV 导出和操作日志按现有格式带上新的两种类别。

## 4. 管理端

**团队**（`#/team`，所有者和管理员），一页从上到下：

1. 「请下午茶」按钮（见 §6）。
2. **等你点头**：确认制下显示；自觉制下还有没处理完的申请时也显示。每条可确认交付、拒绝，或替成员取消（现有）。
3. **大家**：上面是「邀请成员」；每人一行：名字、角色、用户名、可用余额、一共收到、状态。这一行本身是个按钮，点开才露出对这个人的操作（新的登录链接或邀请链接、密码重置链接、更改角色、停用或重新启用），刚生成的链接和二维码也显示在这里；一次只展开一个人。自己那一行，以及管理员看所有者和其他管理员时，没有可展开的内容。在某人那一行做了改动之后页面重画，这一行重新展开，键盘焦点回到它上面。
4. **福利**：只在确认制下显示。清单加「添加福利」「编辑」；添加或编辑时可以从主题的 39 款点心里挑一个当图标（「配个图」），也可以「不配」，点心名按界面语言显示。
5. **记录**：全团队的记录，最近 20 条，「显示更多」继续分页。每条按类别给操作：下午茶可「收回」、自己记的可「改一下」、已完成的兑换可「退回」，都要写原因；更正过的一行带标记（收回了 / 改回了 / 已退回）。同一批下午茶合成一行（见 §6）。上面是「下载账本（CSV）」。
6. **谁做了什么**：只给管理员看（管理员没有设置页）。和设置页里的是同一份操作日志，只读，分页，放在「记录」下面、占满整页宽度。所有者在设置页看，团队页上不显示。

**设置**（`#/settings`，仅所有者），一页：组织（名称、默认语言、欢迎语）、奖励规则（现有，锁定规则不变）、**大家怎么花**、联系与反馈、logo、你的数据（CSV 下载和备份说明）、**谁做了什么**（原「活动」页，放最底，分页；管理员在团队页看，见上）。

权限不变：管理员看团队不看设置，和所有者一样能读操作日志（`GET /api/admin/audit`）；服务器仍逐项复核。

## 5. 页头与导航

- 页头永远一行。
- 成员：左边吉祥物或 logo 加团队名，右边名字胶囊，点开是语言、退出登录。
- 所有者和管理员：宽屏（720px 及以上）时，页头中间放「我的 / 团队 / 设置」三个胶囊按钮（管理员没有设置）；窄屏时这几项收进右上角的名字菜单里，和语言、退出登录放一起。按 Esc 关菜单，键盘焦点回到名字上。
- 登录、加入、重置密码等未登录页面不变。

## 6. 批量请下午茶

- 「请下午茶」对话框里，「请谁」是一张可多勾的名单，列出全部在职的人（含管理员和自己，自己标「（你）」），上面有「在职的全选」和「清空」。只勾一个人时和原来完全一样：走原来的单人接口，按钮写「送出」。
- 每人同一金额（「每人多少」）、同一句留言（「说句话」，不写也行）。勾了两个人以上、金额有效时，按钮写「请 3 个人 · 共 $60.00」。
- 服务器接口 `POST /api/admin/grants/batch`（`userIds`、`amount`、`mode`、`reason`）：一批放在同一笔事务里，要么全记上要么全不记；每个人各得一条 `grant` 账目，各自结算解锁，同一批的账目共用一个 `batch_id`；整批共用一个幂等键，名单按集合读（同样的人换个顺序还是同一批），重发返回同一结果。名单为空、含非在职账号、超过 500 人都拒绝。
- 操作日志每人一条（现有的 `grant.create`），详情里带同一个 `batchId`。
- 团队页的「记录」把同一批合成一行：每人的金额、人数、谁请的、时间和留言（「每人 +$20.00」「3 人 · …」）；同一批的账目跨了分页也还是一行（每条账目都带整批的人数）。点「看全部」展开，列出这一批的每个人和各自的金额，每人一个自己的「收回」；名单一次取全，不管这一行是从哪一页来的。收回其中一人后，页面重画，这一批仍然展开。只有一个人的一批就按普通的一条显示。

## 7. 视觉

以原来那个福利网站的画风为准，应用的样式表改成同一套值；公共演示页（`index.html`）已经是这套画风，不动。

- 背景：米色加 24px 淡格纹（现有）。
- 主卡与区块：白砖，无边框，底影 `0 6px 0 rgba(122,74,38,.18), 0 10px 26px rgba(74,47,27,.1)`，圆角 20px。
- 收藏格：42px，圆角 10px，2.5px 边框 `#a9793f`，内阴影上深下亮。
- 按钮：木色实心，底影 `0 5px 0`，按下时下移 4px；次要按钮浅色同样做法。
- 记录条：木色标题栏，金色菱形，行间虚线分隔。
- 弹层：手机上从底部升起的面板（带抓手条）；宽屏时居中对话框。现有的 `<dialog>` 机制不变，只换样式。
- 提示（toast）从顶部落下；手机上落在页头下面，大字号时也不压住页头。
- 小字颜色保持现有较深的一档，以过 WCAG AA。
- 管理端用同一套：区块是白砖，列表是虚线行，表单控件按原版键盘和面板的风格。
- 缩减动效（`prefers-reduced-motion`）时所有动画关闭，功能不受影响。

## 8. 动画

五处，全部从公共演示页现成的原生 JavaScript 移植（`assets/app.js` 里的 `ovenIntro`、大数字滚动、格子落下、掉屑），放在 `app/motion.js`：

1. **开场出炉**：已经登录的人打开页面时，吉祥物弹出，一句「今天的下午茶出炉啦」和「点一下跳过」，0.9 秒后开始退场（退场 0.42 秒），点一下直接跳过。只在打开页面时出现一次，页内切换不重放；登录页和登录链接页不放。
2. **主卡滑入**：开场退场后主卡从上方落定，只在这一次。
3. **大数字滚动**：从这台设备上次看到的余额滚到现在的；每次记账后从旧值滚到新值，扣款时数字轻轻一缩，增加时轻轻一跳。「上次看到的」存在浏览器本地，键名 `crumb.seen.<成员 id>`，只有三个数字（余额、点心件数、累计收到），而且只存这台浏览器上现在登录的那个人的：退出登录时删掉；页面一发现这里没人登录或换了人（新的登录链接、停用、会话过期），也删掉，哪怕当时页面关着、下次打开才发现。
4. **点心落格**：首次进入时全部点心逐个落下（每个隔 70 毫秒）；之后只有这台设备上次看过以后新解锁的落下。
5. **点吉祥物掉屑**：点左上角老婆饼，抖一下并掉饼屑。

缩减动效时：没有开场，点心不落，大数字直接画出新值。

不做：消费后吉祥物被咬一口（成员端没有对应的时刻）。

## 9. 措辞

「认可」这个词在中英两套应用文案里全部替换，方向一致。定稿如下：

| 位置 | 中文 | 英文 |
| --- | --- | --- |
| 团队页按钮、对话框标题 | 请下午茶 | Treat someone |
| 展开后的记录 | Priya 请的 +$25.00 | Treat from Priya +$25.00 |
| 累计（团队页每人一行） | 一共收到 | Received so far |
| 批量按钮 | 请 3 个人 · 共 $60.00 | Treat 3 people · $60.00 all in |
| 开场 | 今天的下午茶出炉啦 | Today’s treats are out of the oven! |
| 收回一次下午茶 | 收回 | Take back |
| 更正一笔自己记的 | 改一下 | Fix |
| 收回后的标记 | 收回了 | Taken back |
| 改回后的标记 | 改回了 | Put right |
| 记账按钮 | 我拿了东西 | I grabbed something |
| 键盘的确认 | 记下 | Jot it down |
| 收到了新的下午茶 | 有人请你下午茶啦，+{amount} | Someone treated you: +{amount} |
| 两种花法 | 自己记 / 要确认 | Self-recorded / Confirmed |

成员端记录条里的类别只用短词：下午茶 / 自己记的 / 兑换 / 退回 / 改动（Treat / Jotted down / Redeemed / Refunded / Fixed）。其余文案以 `app/locales/en.js` 和 `app/locales/zh-CN.js` 为准。

README 的标语和简介句（公共演示页和它共用）本轮不改写，其余文字按新措辞改；新增「换成你自己的」一节，并用一句话解释名字：面包吃完了，饼屑还在。

## 10. 数据与接口

迁移 `002`：

- `organization` 加 `spending TEXT NOT NULL DEFAULT 'self' CHECK (spending IN ('self','confirm'))`。已有的组织：已经有福利条目的设为确认制，否则自觉制。
- `ledger.kind` 的约束扩成 `('grant','revoke','redeem','refund','spend','void')`，正负号和来源行的约束相应调整：`grant`、`refund`、`void` 为正，`grant`、`spend` 没有来源行；新增 `batch_id` 列，只有 `grant` 能带。SQLite 不能改约束，迁移用「建新表、复制、删旧表、改名、重建索引和触发器」的方式（多一个 `ledger_by_batch` 索引），行和 id 都不变。
- `rewards` 加 `icon_key TEXT`，可空（2 到 32 个字符）；写入时服务器校验是主题里的键。
- 迁移在一笔事务里跑，期间关闭外键检查（SQLite 重建被别的表引用的表只能这样）；跑完、提交之前逐条检查所有引用，有任何一条会指向不存在的行，就整次拒绝、什么都不改，Crumb 不启动并说明是哪几行。已经是最新版本的数据库不做这项检查：一条无关的旧坏行不能拦住 Crumb 或在服务器上找回所有者账户。

接口：

- `POST /api/me/spend`（成员，幂等）；`POST /api/admin/spends/:id/void`（管理员，幂等，必须写原因）。
- `POST /api/admin/grants/batch`（管理员，幂等），返回 `{ batchId, count, units, unlocked, entries }`。
- `PATCH /api/org` 接受 `spending`；`POST /api/setup` 的 `org` 也接受。
- `GET /api/me`、`GET /api/session` 返回 `org.spending`；`GET /api/rewards` 和管理端福利接口带 `iconKey`；`GET /api/admin/rewards` 还返回主题的键和三种语言的名字，图标选择器只列服务器接受的键。
- 账目视图（`/api/me/ledger`、`/api/admin/ledger`）`kind` 新增两种，并带 `batchId` 和三个标记：`corrected`（被收回的下午茶或被改回的记账）、`revoked`（只用于下午茶）、`refunded`（被退回的兑换，单独一个标记，不算在 `corrected` 里）。`/api/admin/ledger` 每条还带 `batchSize`，并接受 `?batchId=`，列出一整批。
- `GET /api/me/redemptions` 接受 `?status=`：切到自觉制后，成员页用它列出全部还在等的申请。
- 自觉制下 `POST /api/redemptions` 返回 `SPENDING_MODE`；确认制下 `POST /api/me/spend` 也返回 `SPENDING_MODE`。
- CSV 的 kind 列同步。

## 11. 换皮与复用

目标是「下载、改设置、能用」，不改代码：

- 不改代码就能换的：团队名、logo、默认语言、额度名、币种或积分、解锁台阶、欢迎语、花钱方式、联系方式、反馈链接。全部在建团队和设置页里。
- 改一个文件就能换的：一整套点心（`docs/THEMES.md`）。本轮不做换皮，但福利图标从主题里取，为下一轮留好接口。
- README 加「Make it yours / 换成你自己的」一节，列出上面两类；说明典型使用者是面包店、咖啡厅、奶茶店这样的小店，也适合任何小团队。

## 12. 本轮不做

- 主题换皮（面包店的面包和蛋糕、咖啡店的咖啡）：下一轮，主题在建团队时选、第一件解锁后锁定。
- 成员端分页、底部标签、感谢列表。
- 成员自己撤销记账。
- 「咬一口」动画。
- 既有待定项（账号锁定、管理员给自己发放、匿名会话写行等）不在本轮。

## 15. 假设（按批准稿实施）

设计按下面的假设批准，实施照此做：

1. 默认花钱方式是自觉制；`npm run demo` 的示例团队也用自觉制，README 里说明怎么切到确认制。
2. 已有数据库升级时，如果已经有福利条目，迁移自动把花钱方式设为确认制；否则设为自觉制。
3. 成员页不显示累计收到的数额、总件数和台阶（管理端每人一行显示累计）。
4. 请下午茶的「留言」保留但可不填；成员只在展开全部记录时看到留言。
5. 自觉记账的面板只输金额，不选品项、不写备注。
6. 管理端团队页的「记录」默认显示最近 20 条，展开后分页。
7. 开场动画每次打开页面出现一次（刷新也会出现），不做「每天一次」。

## 16. 实施时定下的、和批准稿不一样的地方

- **动作区下面的灰字**：不是每种花法一句固定提示，而是每天一句，按日期轮换（七句）；可用余额为零时换成更温和的一组（四句）。
- **措辞定稿**：见 §9 的表。和批准稿不同的有：「请下午茶 / Treat someone」、「收回 / Take back」、「改一下 / Fix」、「改回了 / Put right」、「自己记的 / Jotted down」、类别「改动 / Fixed」、开场「今天的下午茶出炉啦 / Today’s treats are out of the oven!」、批量按钮「请 3 个人 · 共 $60.00 / Treat 3 people · $60.00 all in」；其余以 `app/locales` 为准。
- **收到新下午茶的提示**：这台设备上次看过之后收到了下午茶，成员页提示「有人请你下午茶啦，+{amount} / Someone treated you: +{amount}」。
- **团队记录里的一批**：一行写明每人金额和人数，点开列出每个人，每人有自己的「收回」。
- **「大家」里的每个人**：一行点开才显示对这个人的操作，长名单在手机上也短。
- **「已退回」标记**：被退回的兑换有自己的标记和自己的 `refunded` 标志，不算作「更正」。
- **「上次看到的」数字**：在设备上按人存，只留现在登录的这个人的，退出登录时、以及页面发现没人登录或换了人时删掉。
- **浏览器里的幂等键**（`crumb.pending`）：每笔还没等到回应的改动，记下它的幂等键和这笔改动的指纹，连同这个人的 id、改动的种类和发出的时间。这些留在这台浏览器上，等到回应为止，最多用七天（超过七天的，下次在这台浏览器上打开 Crumb 时删掉），而且只留现在登录的这个人的：和「上次看到的」数字一样，这个人退出登录、或者别人在这台浏览器上登录时删掉，页面发现没人登录时也删掉。在那之前，用同一台浏览器的人能从指纹推算出很小的改动，比如一个金额。退出登录时还有改动没等到回应的，那笔「没确认」的提示也跟着没了。
- **退出登录要服务器确认**（评审之后定的）：服务器确认这台浏览器的会话已经结束，才算退出。一次只进行一个退出，十秒内没等到回应的，算没退出。因为同一个人在别的标签页又登录了一次而被拒的，再发一次；如果这之后别人在这台浏览器上登录了，那次登录已经结束了要离开的人的会话，所以这次退出算数，别人保持登录。退出算数之前，浏览器里什么都不删，页面保持登录并说明退出没成功；算数之后，页面显示服务器现在说的状态，即使服务器接下来没回应，也照样显示登录页。
- **管理员看「谁做了什么」**（评审之后定的）：批准稿只把操作日志放在设置页，管理员打不开。现在管理员在团队页最底下看，只读，和 0.1 版里能看「活动」页一样；所有者只在设置页看。
- **迁移的引用检查**：只在真的跑了迁移之后做；会留下悬空引用就拒绝，什么都不改。
- **新增的读取接口**：`GET /api/me/redemptions?status=`、`GET /api/admin/rewards` 带主题的键和名字、`/api/admin/ledger` 的 `batchSize` 和 `?batchId=`（见 §10）。
